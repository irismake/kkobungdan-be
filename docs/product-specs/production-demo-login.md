# 운영 데모 로그인 인증

## 사용자 문제

일반 사용자는 실제 SMS 인증번호로 가입하고 로그인해야 한다. 동시에 운영 환경을 검수하는 사용자는
실제 SMS 수신 없이 정해진 데모 계정으로 로그인할 수 있어야 한다.

## 기대 행동

| 용도 | 전화번호 | 인증번호 | 계정 이름 |
|---|---|---|---|
| 로그인 데모 | `010-0000-0000` | `123456` | `오더런 데모` |

- 일반 회원가입과 일반 로그인에는 매 요청마다 새로 생성한 6자리 인증번호를 SMS로 발송한다.
- 로그인 데모 번호의 인증번호 발송 요청에는 `123456` 인증을 생성하지만 SMS 발송 작업을 등록하거나 SMS 공급자를 호출하지 않는다.
- 데모 번호가 실제 사용 중인 전화번호이더라도 SMS를 보내지 않는다.
- 데모 로그인도 일반 인증과 같은 발송 요청, 유효시간, 실패 횟수, 최신 인증번호 규칙을 따른다.
- 로그인 데모 사용자가 탈퇴된 경우 다음 로그인 인증번호 요청에서 데모 사용자를 복구한다.
- 회원가입에는 데모 예외가 없으며, 로그인 데모 번호의 회원가입 발송 요청은 SMS 없이 이미 가입된 번호로 거절한다.
- 전화번호나 용도가 일치하지 않으면 `123456`은 데모 코드로 취급하지 않는다.
- staging과 production 모두 같은 데모 로그인 정책을 적용하며 어느 환경에서도 SMS 공급자를 호출하지 않는다.

## 완료 조건

- 일반 회원가입과 로그인 SMS에는 고정값이 아닌 새 6자리 인증번호가 포함된다.
- 로그인 데모 번호는 운영 데이터베이스에 존재하며 발송 요청 후 `123456`로 로그인할 수 있다.
- 로그인 데모 발송 요청은 SMS 공급자를 호출하지 않는다.
- 모든 일반 회원가입 번호와 일반 로그인 번호는 발송된 실제 인증번호 없이 `123456`만 입력해 인증할 수 없다.

## 운영 주의사항

- 데모 인증정보는 의도적으로 공개되는 검수용 자격 증명이다. 실제 사용자 계정이나 비밀정보로 사용하지 않는다.
