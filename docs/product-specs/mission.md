# 미션 (Mission)

> 상태 흐름 시각화: [요청·지원·미션 상태 지도](https://claude.ai/code/artifact/bf76f755-a2be-4ac9-b9be-71733dc73f1b)

## 사용자 문제

행님이 꼬붕을 선택하면 실제 심부름 수행이 시작된다. 이 수행 단위는 앱에서는 요청과 지원으로 나뉘어
보이지만, 웹 관리자는 하나의 수행 건으로 추적하고 정산·환불까지 처리해야 한다. 현재 서버에는 이
수행 단위를 나타내는 엔티티가 없어 관리자가 요청과 지원을 각각 조회해 상태를 조합해야 한다.

## 기대 행동

### 미션 생성

- 행님이 꼬붕의 지원을 선택하는 시점(`Offer.ACCEPTED` + `Proposal.MATCHED`)에 미션을 생성한다.
- 미션은 수락된 지원 하나와 1:1로 대응한다. 하나의 요청에는 최대 하나의 미션만 존재한다.
- 미션 생성 시 최초 상태는 `미션 시작`이다. 생성과 진행을 구분하지 않는다.

### 미션 상태

| 상태 | 표기 | 의미 |
|---|---|---|
| `STARTED` | 미션 시작 | 꼬붕이 선택되어 수행이 진행 중이다 |
| `DISPUTED` | 분쟁중 | 요청 또는 지원이 분쟁 상태로 전환되었다 |
| `COMPLETED` | 미션 완료 | 수행이 정상 종료되었다. 꼬붕에게 수행비를 지급해야 한다 |
| `PAID` | 입금 완료 | 꼬붕에게 수행비 지급을 마쳤다 |
| `FAILED` | 미션 실패 | 수행이 실패로 종료되었다. 행님에게 환불해야 한다 |

- `미션 완료`는 정산 대기 상태를 겸한다. 별도의 정산 대기 상태를 두지 않는다.
- `미션 실패`는 수행 결과이며 환불 대기·완료 상태는 별도 Refund에서 관리한다.
- 꼬붕만 수행 완료를 확인했거나 행님만 수령을 확인한 중간 시점에도 미션 상태는 `미션 시작`을
  유지한다.
- 관리자가 한쪽만 확인한 상황을 바로 볼 수 있도록 미션 응답에 양측 확인 시각을 함께 담는다.
- 미션 응답은 수행 상태인 `status`와 별도로 수행비 지급 처리 상태인 `settlementStatus`를 함께 담는다.
  `settlementStatus` 값은 `PENDING`, `COMPLETED`, `REJECTED`다.

| 항목 | 의미 |
|---|---|
| 꼬붕 수행 완료 시각 | 꼬붕이 수행 완료를 누른 시각. 없으면 아직 누르지 않았다 |
| 행님 수령 확인 시각 | 행님이 수령을 확인한 시각. 없으면 아직 누르지 않았다 |

- 확인 시각의 정본은 지원 한 곳이며 미션에 복제해 저장하지 않는다. 조회 시점에 합쳐서 내려준다.

### 상태 전이

```
미션 시작 ─┬─ 양측 확인 완료 ──────────────→ 미션 완료 ──→ 입금 완료
           ├─ 분쟁 발생 ──→ 분쟁중 ─┬─ 관리자 완료 판정 ──→ 미션 완료 ──→ 입금 완료
           │                         └─ 관리자 실패 판정 ──→ 미션 실패
           └─ 관리자 요청 취소 ─────────────────────────→ 미션 실패
```

- `미션 시작` → `미션 완료`: 요청과 지원이 모두 `ALL_COMPLETED`가 될 때 자동 전이한다.
- `미션 시작` → `분쟁중`: 요청 또는 지원이 `DISPUTED`가 될 때 자동 전이한다.
- `분쟁중` → `미션 완료` 또는 `미션 실패`: 관리자가 분쟁 해결 시 판정 결과를 선택해 전이한다.
- 완료 판정이면 Proposal/Offer는 `ALL_COMPLETED`, 실패 판정이면 Proposal은
  `REFUND_PENDING`, Offer는 `CANCELLED`가 된다. 분쟁 처리 완료 자체는
  `DisputeEvidence.status=RESOLVED`에 기록한다.
- `미션 완료` → `입금 완료`: 관리자가 꼬붕 수행비 지급을 기록할 때 전이한다.
- `입금 완료`는 종료 상태다. `미션 실패`도 수행 결과가 확정된 종료 상태이며 환불 처리로
  상태가 바뀌지 않는다.
- 미션 시작 전 단계에서의 요청 취소·지원 취소는 미션이 존재하지 않으므로 미션 상태로 표현하지
  않는다. 단, 입금 확인된 `POSTED`/`OFFERED` 요청 취소는 Refund를 만들고 Proposal을
  `REFUND_PENDING`으로 전이한다.
- 앱에서 행님이 직접 취소할 수 있는 구간은 매칭 전까지다. 미션 시작 후 행님·꼬붕의 취소는
  분쟁을 거쳐 관리자가 `미션 실패`로 판정하는 경로로만 가능하다.
- 관리자는 요청 취소로 미션을 종결할 수 있다. 미션에는 취소 상태가 없으므로 `미션 실패`로
  종결하고 Proposal은 `REFUND_PENDING`, 수행 중이던 지원은 `CANCELLED`가 된다.
- 관리자 요청 취소는 미션이 `미션 시작` 또는 `분쟁중`일 때만 허용한다. `미션 완료`,
  `입금 완료`, `미션 실패` 미션이 붙어 있으면 취소를 거절한다.
- 미션만 단독으로 실패 처리하는 API는 제공하지 않는다. 실패는 분쟁 판정 또는 요청 취소의
  결과로만 발생한다.

### 분쟁 해결 판정

- 모든 분쟁 증빙은 생성 시점부터 하나의 미션에 반드시 연결한다.
- staging의 기존 분쟁 증빙은 연결된 `offer_id`의 미션으로 백필한 뒤 `mission_id`를 NOT NULL FK로 전환한다.
- 관리자가 분쟁을 해결할 때 `완료` 또는 `실패` 중 하나를 반드시 선택한다.
- `완료` 판정: 꼬붕이 수행을 마친 것으로 인정하고 수행비를 지급한다.
- `실패` 판정: 수행이 이루어지지 않은 것으로 보고 행님에게 입금액 전액을 환불한다.
- 판정 결과와 판정한 관리자, 판정 시각을 미션에 기록한다.
- 분쟁 처리 자체의 상태(`PENDING`, `RESOLVED`, `REJECTED`)는 분쟁 증빙이 가진다. 관리자가
  분쟁 접수를 반려(`REJECTED`)하면 요청·지원·미션 상태는 그대로 유지된다.
- `실패` 판정은 환불 대상을 확정할 뿐이며 실제 환불 완료는 Refund에서 별도로 기록한다.

### 지급 여부 기록

- 수행비 지급과 환불은 서버가 이체를 실행하지 않는다. 관리자가 실제 이체를 수행한 뒤 결과를 기록한다.
- 수행비 지급은 Mission, 환불은 Refund가 각각 정본이다.
- 미션은 다음을 기록한다.

| 항목 | 의미 |
|---|---|
| 수행비 지급 여부 | 꼬붕에게 수행비가 입금되었는지 |
| 수행비 지급 시각 | 관리자가 지급을 기록한 시각 |
| 수행비 지급 처리자 | 지급을 기록한 관리자 |
| 지급 메모 | 이체 참조번호 등 관리자 입력 메모 |

- 금액은 관리자가 입력하지 않는다. 수행비 지급액과 환불액은 모두 요청의 수행비(`errand_fee`) 전액이다.
- 부분 환불은 지원하지 않는다.
- `PAID`는 수행비 지급 완료를 의미한다. `COMPLETED`는 지급 대기이며, `FAILED`는 환불 처리와
  무관하게 실패로 확정된 수행 결과다.

## 완료 조건

- 행님이 꼬붕을 선택하면 미션이 자동 생성되고 `미션 시작` 상태가 된다.
- 요청과 지원의 상태 변화가 미션 상태에 반영된다.
- 관리자가 분쟁 미션을 완료 또는 실패로 판정할 수 있다.
- 관리자가 수행비 지급을 기록해 `입금 완료`로 전이시킬 수 있다.
- 관리자 웹은 환불을 Refund 목록과 상세에서 확인하고 완료 처리할 수 있다.
- 관리자 웹에서 꼬붕과 행님이 각각 언제 완료를 눌렀는지 미션 화면에서 확인할 수 있다.
- 관리자 웹에서 매칭된 미션의 카카오톡 오픈채팅방 링크를 확인할 수 있다.
- 관리자 수행비 지급 목록은 별도 요약 DTO를 만들지 않고 `MissionResponse`를 그대로 사용한다.
- 관리자 미션 응답의 행님·꼬붕 이름은 non-null 문자열이다. 이름이 지워졌거나 사용자 row를 찾을 수
  없으면 `"탈퇴한 사용자"`로 표시한다.
- 관리자 웹에서 미션 목록을 상태로 필터링해 조회할 수 있다.

## 비범위

- 앱 클라이언트는 미션을 사용하지 않는다. 앱 API에 미션을 노출하지 않는다.
- 실제 이체 실행이나 PG 연동은 포함하지 않는다.
- 부분 환불과 분할 지급은 지원하지 않는다.
- 기한 만료 미션 자동 처리와 신고에 의한 강제 종료는 이번 범위에 포함하지 않는다.
