# 실제 SMS 인증번호 및 운영 데모 계정

## 목표

- 일반 전화번호의 고정 인증번호를 제거하고 실제 임의 인증번호를 사용한다.
- 운영 환경에서 로그인 흐름을 검수할 수 있는 데모 전화번호 한 개를 제공한다.

## 범위와 비범위

- 범위: 인증번호 생성, 로그인 데모 번호 인증 정책, 로그인 데모 사용자 시드와 복구, 인증 회귀 테스트, 관련 문서.
- 비범위: SMS 공급자 설정 변경, 인증 API 요청·응답 계약 변경, 기존 일반 사용자 데이터 변경.

## 가정

- 로그인 데모 번호는 `01000000000`을 사용하고 회원가입 데모는 제공하지 않는다.
- 로그인 데모 번호에는 SMS 발송 작업을 등록하거나 SMS 공급자를 호출하지 않으며 `123456`을 저장·검증한다.
- 데모도 발송 요청 이후의 pending verification을 검증해 기존 TTL과 실패 횟수 정책을 유지한다.

## 완료 작업

1. 일반 인증번호 생성기를 보안 난수 기반 6자리 값으로 복구했다.
2. 로그인 목적과 데모 전화번호가 모두 일치할 때만 `123456`을 사용하고, 데모 번호의 로그인·회원가입 발송 모두 SMS 공급자 호출을 생략했다.
3. 로그인 데모 사용자를 마이그레이션으로 추가하고 탈퇴 후 로그인 발송 시 복구하도록 했다.
4. 일반 회원가입·로그인과 데모 로그인 경계 테스트를 갱신했다.
5. 제품 스펙과 User/Auth 테스트 보장 문서를 현재 정책에 맞췄다.

## 검증 결과

- `.venv/bin/python -m compileall -q app alembic/versions/0021_seed_demo_login_user.py`: 통과.
- `tests/test_phone_verification.py`, `tests/test_config.py`, `tests/test_openapi.py`, `tests/test_errors.py`: staging/production 데모 SMS 미호출을 포함해 51개 통과.
- `alembic heads`: `0021_seed_demo_login_user (head)` 확인.
- 변경된 MySQL 인증 통합 테스트는 실행을 시도했으나 로컬에 Docker 명령이 없고 `127.0.0.1:3307` 테스트 DB도 실행 중이지 않아 연결 거절로 완료하지 못했다.

## 롤아웃 및 롤백 메모

- 앱 배포 후 `0021_seed_demo_login_user` 마이그레이션이 로그인 데모 사용자를 멱등하게 추가한다.
- 애플리케이션 롤백 시에도 시드 사용자는 남을 수 있으나 기존 인증 우회가 운영에서 허용되지 않아 일반 사용자로 취급된다.

## 남은 리스크

- 배포 전 또는 CI에서 `mysql-test`가 healthy인 상태로 변경된 인증 통합 테스트와 fresh DB `alembic upgrade head`를 실행해야 한다.
