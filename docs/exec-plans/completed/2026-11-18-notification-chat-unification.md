# 지원 전 알림·지원 후 시스템 채팅 통합

> 상태: 완료 (2026-11-18)
> 기준: [NOTI-REQ-001](../../product-specs/notification-policy.md#noti-req-001--지원-전후-전달-정책), [채팅 요구사항](../../product-specs/chat-requirements.md)

## 목표

지원 전에는 푸시 알림(클릭 시 요청 상세), 지원 후에는 시스템 채팅(클릭 시 채팅방)으로 전달 경로를 하나로 정리한다.

- [x] 전달·문구·클릭 정책 정리. 기존 문구 보존, 신규 취소·환불 문구 정의.
- [x] Red: 신규 알림·환불 경로 및 기존 문구/제목·푸시 전환 테스트 실패 확인과 커밋.
- [x] Green: 기존 지원 이후 알림 제거, 시스템 문구·제목·수신자 통합, 신규 알림 3종과 매칭 전 환불 안내.
- [x] 문서·API 계약·기존 회귀 테스트 갱신, scripts/verify.sh 통과.

## 실제 반영 내용

- 지원 이후 기존 알림 6종(지원·매칭·완료 확인·분쟁) 생성을 제거하고, 문구·제목을 수신자별 시스템 채팅으로 옮겼다. 미선정 행님을 뺀 모든 수신자에게 시스템 채팅 푸시를 보낸다.
- 시스템 채팅 응답·실시간 이벤트에 `systemTitle`을 추가했다. 푸시 제목은 시스템 제목, 없으면 상대 이름이다.
- 지원 이력이 없는 요청의 취소·환불은 알림 3종(`PROPOSAL_CANCELLED_BY_USER`, `PROPOSAL_CANCELLED_BY_ADMIN`, `REFUND_COMPLETED`)으로 행님에게 보낸다. 푸시 data에 `proposal_id`를 담는다.
- 매칭 전 환불도 그 요청의 모든 채팅방(닫힌 방 포함)에 안내한다.
- `notification_type`은 CHECK 제약 없는 `String(50)`이라 마이그레이션은 필요 없다.

## 검증 기록

- Red: 신규 테스트 21건 실패 확인 (`f0415f5`, 원래 `b2f0ae2`). 취소된 지원 이력의 오래된 조회로 인한 중복 알림 재현 (`adf012c`).
- 신규 경로 19건 통과 후, 중복 환불 완료 API의 기존 계약(409)을 테스트에 바로잡음.
- 회귀: `bbd460f`에서 `scripts/verify.sh all` 통과 — 시나리오 445/445 연결, 537 passed, 8 skipped, 실패 0.

## 범위와 후속 작업

요청 만료 안내·자동 만료(TD-021)는 사용자 결정으로 보류. 완료 리마인드는 기존 미구현 유지. 신고 승인 안내(TD-027), 오픈채팅 필드 제거(TD-020)는 별도 작업. 앱은 `systemTitle` 표시와 신규 알림 타입의 요청 상세 라우팅을 반영해야 한다. 실제 모바일 클릭·푸시 표시는 이 서버 저장소에서 검증할 수 없다.
